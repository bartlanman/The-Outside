# COLLISION FIELD RUN PROTOCOL

**Status:** Canonical execution controller — hard contract  
**Office:** Masterwork Formation  
**Authority:** This file owns the order of operations for every full Collision Field run.  
**Invocation:** `collision field`, `run collision field`, `collision field [number/title/name]`, or clear equivalent.

---

# 0. GOVERNING LAW

A Collision Field run is not a loose collection of related operations.

It is a staged execution.

> **NO STAGE MAY BE SKIPPED, SILENTLY INFERRED, MERGED INTO ANOTHER STAGE, OR REORDERED.**

If a subordinate file conflicts with this controller, this controller governs the sequence.

Subordinate protocols govern the quality and internal method of their own stage; they do not own the run order.

Canonical run:

> **RELOAD CANON → RECOVER FIELD → GRAVITY → POET SING → ΔΙΑ ⇄ ΣΥΝ → MASTERWORK → GRAPHIC PROMPT → EXEGESIS → LINT → PROMPT LOCK → STOP**

Image phase:

> **USER IMAGE COMMAND → RELOAD CANON → RECOVER LOCKED PROMPT VERBATIM → LINT AGAIN → GENERATE GRAPHIC → JUDGE**

---

# 1. REQUIRED SOURCE MANIFEST

Before producing CF-01 or later, re-read the relevant repository material.

Minimum required canon:

1. the requested Collision Field source file;
2. `Masterwork-Formation/Synthesis/MASTERWORK_PROLIFERATION_METHOD.md`;
3. `Masterwork-Formation/Follow/FOLLOW_AEOLIAN_POET.md`;
4. `Masterwork-Formation/Synthesis/CHAPTER_FORMATION_LAW.md`;
5. `Masterwork-Formation/Protocols/MASTERWORK_CREATION_PROTOCOL.md`;
6. `Masterwork-Formation/Protocols/COLLISION_FIELD_GRAPHIC_PROTOCOL.md`.

When graphic formation requires current visual grammar, also read the relevant Visual Art genealogy / pressure-field files named by the graphic protocol or by the active field.

Do not reconstruct these rules from conversational memory.

> **REPOSITORY CANON OVERRIDES REMEMBERED PRACTICE.**

The run must begin with:

> **CF-00 — CANON LOADED**

and name the specific field source recovered.

---

# 2. CF-01 — FIELD RECOVERED

Recover the actual field from the repository.

Do not summarize from memory.

Preserve:
- the materials that entered the field;
- their different standing;
- unresolved tensions;
- remainders;
- prior gravities;
- factual / historical / symbolic distinctions that must not be flattened.

This stage is recovery, not creation.

Output header:

> **CF-01 — FIELD RECOVERED**

---

# 3. CF-02 — GRAVITY

Identify the pressure that is pulling the recovered field together.

Gravity is not:
- a summary;
- a doctrine;
- a theme label;
- a thesis imposed before the field speaks.

Gravity is the live attraction / pressure that makes the materials begin to organize without erasing their difference.

Output header:

> **CF-02 — GRAVITY**

---

# 4. CF-03 — POET SING

The Aeolian Poet enters as a tensioned instrument.

This stage must follow `FOLLOW_AEOLIAN_POET.md`.

The Sing is not:
- an explanation;
- a summary;
- an essay;
- a chapter by default;
- narrative fiction by default;
- a decorative paragraph;
- a proof of a predetermined title.

The poet sounds the field.

The poet creates adjacency rather than forcing synthesis.

The Sing must be substantial enough for the field's pressure to become audible, but its length and form are earned by the field.

> **SING ≠ MASTERWORK BY DEFINITION.**

The Sing is the sounding operation.

It may later be judged sufficient to stand as the Masterwork, but that judgment belongs to CF-05.

Output header:

> **CF-03 — POET SING**

---

# 5. CF-04 — ΔΙΑ ⇄ ΣΥΝ

Only after the Sing exists, listen back through:

# **διά ⇄ σύν**

Ask:
- what passes through?
- what gathers?
- what becomes possible only through passage?
- what becomes perceptible only because something temporarily holds?
- where does holding become constraint?
- where does passage become dispersal?
- what relation was audible only after the poet sounded the field?

Do not apply διά ⇄ σύν as a prefabricated doctrine.

Read it from the completed Sing.

If a name/title emerges, it must be earned here rather than imposed upstream.

Output header:

> **CF-04 — ΔΙΑ ⇄ ΣΥΝ**

---

# 6. CF-05 — MASTERWORK

Now invoke:

`Masterwork-Formation/Protocols/MASTERWORK_CREATION_PROTOCOL.md`

This is a separate stage.

The system must decide what form, if any, the field now warrants.

Hard rule:

> **DO NOT DEFAULT TO A NOVEL, CHAPTER, ESSAY, POEM, SCRIPT, OR ANY OTHER PRESELECTED FORM.**

Possible results include:
- the Sing itself is sufficient and becomes the Masterwork;
- the Sing becomes the seed of a different work;
- a chapter is warranted;
- a short lyric, dramatic scene, sequence, score, hybrid, visual-text object, or other form is warranted;
- no additional literary artifact is warranted yet.

Never manufacture a second artifact merely because the checklist contains a Masterwork stage.

Output header:

> **CF-05 — MASTERWORK**

The stage must state:

> **MASTERWORK FORM:** [earned form]

and then create only what is warranted.

---

# 7. CF-06 — GRAPHIC PROMPT

Only after CF-05 is complete, invoke:

`Masterwork-Formation/Protocols/COLLISION_FIELD_GRAPHIC_PROTOCOL.md`

The visual stage must be downstream of:
- the recovered field;
- gravity;
- Sing;
- διά ⇄ σύν;
- the Masterwork determination.

Output header:

> **CF-06 — GRAPHIC PROMPT**

The graphic prompt must be complete enough to generate without later invention.

---

# 8. CF-07 — EXEGESIS

Read the intended graphic back through the actual run.

The exegesis must account for:
- field;
- gravity;
- Sing;
- διά ⇄ σύν;
- Masterwork relation;
- material motion;
- human fragment;
- giving / receiving if present;
- what is transformed;
- what resists.

The exegesis is diagnostic.

It may expose a defect in CF-06. If so, revise CF-06 before lint.

Output header:

> **CF-07 — EXEGESIS**

---

# 9. CF-08 — LINT

Run the complete lint defined by the graphic protocol.

This lint must be visible.

Output exactly one of:

> **CF-08 — LINT: PASS**

or

> **CF-08 — LINT: FAIL**

If FAIL:
- state the failure;
- revise CF-06;
- update CF-07 if the revision changes the intended reading;
- lint again.

Do not proceed until PASS.

---

# 10. CF-09 — PROMPT LOCK / STOP

After PASS, freeze the exact generation prompt.

Output:

> **CF-09 — GRAPHIC PROMPT LOCKED**

The locked prompt is immutable unless the user explicitly asks to revise it.

Do not paraphrase it later.
Do not "improve" it at generation time.
Do not reconstruct it from memory.

Then:

> **STOP.**

No image generation occurs in the same turn as the full textual run.

---

# 11. IMAGE PHASE

The image phase begins only after an explicit user command such as:
- image;
- graphic;
- create it;
- generate it.

Before generation:

1. re-read this controller;
2. re-read `COLLISION_FIELD_GRAPHIC_PROTOCOL.md`;
3. recover the exact locked prompt from CF-09;
4. run the graphic lint again;
5. if unchanged and PASS, generate from the locked prompt.

No new concepts may be introduced between lock and generation.

---

# 12. POST-GENERATION JUDGMENT

After generation, judge the image against the locked prompt and graphic protocol.

Allowed judgments:

> **KEEP**  
> **REVISE**  
> **DISCARD**  
> **CANONIZE**

Generation does not equal success.

A protocol violation must not be quietly accepted.

---

A full Collision Field text run is valid only if all headers appear in order:

> **CF-00 — CANON LOADED**  
> **CF-01 — FIELD RECOVERED**  
> **CF-02 — GRAVITY**  
> **CF-03 — POET SING**  
> **CF-04 — ΔΙΑ ⇄ ΣΥΝ**  
> **CF-05 — MASTERWORK**

> **CF-07 — EXEGESIS**  
> **CF-08 — LINT: PASS**  
> **CF-09 — GRAPHIC PROMPT LOCKED**

If one is missing, the run is incomplete.

> **DO NOT COMPENSATE FOR A MISSING STAGE BY CLAIMING IT WAS IMPLICIT.**
